# 课记优化与修复实施方案（精简版）

本版替代原来的 16 项方案。实施目标是修复真实缺陷、减少数据覆盖和改善大库性能。方案面向执行代码修改的 Agent，当前仅更新文档，不表示功能已经实施。

初始审阅基线：2026-11-27，Git HEAD `698f005`。实施时重新读取当前源码与适用的 AGENTS.md。使用函数名定位，不依赖旧行号。用户反馈部分 UI 已重构，执行者必须保留这些成果。

## 1. 范围和实施规则

1. 按下表完成前四步。第五步先测量，再实施摘要优化，其他性能改造按证据决定。
2. 每个子任务独立提交或形成独立可审阅差异。先修缺陷，再提取模块。
3. 保留用户未提交的修改。数据迁移不能通过清库完成。
4. 使用现有技术栈和存储格式。已有工具足够时不新增框架。
5. 不引入 IndexedDB jobs 表、心跳租约、执行令牌系统或通用 expectedRevision 框架。
6. 不实现字段级三方同步、父版本链、答题事件溯源、CRDT、跨设备历史同步。
7. 保留现有单文件 WebDAV。按课节分文件只是未来候选方案，本轮不实施。
8. 不强制拆成七个控制器模块，不全面重写 note-schema，不做全仓格式清理。
9. 不重写流式音频解码，不增加 128 MiB 拒绝阈值。
10. 保留现有工具栏、其他形式菜单、编辑器和 AI 助教布局。新增按钮应融入现有入口。
11. 自动测试使用固定数据和模拟服务。不得调用用户的付费模型或生产 WebDAV。
12. 新增的保存失败必须可见。只有数据库确认成功后才能提示“已保存”。

### 执行路线

| 顺序 | 内容 | 依赖 | 交付结果 |
| --- | --- | --- | --- |
| Step 1 | 修订与撤销修复、类型检查 | 无 | AI 修订正确落盘，同类签名错误可检查 |
| Step 2 | 多标签任务保护、缓存安全 | Step 1 | 不误判活跃任务，不清掉用户资产 |
| Step 3 | 局部事务写入、少量撤回快照 | Step 2 | 不覆盖无关字段，同正文过期写入被阻止 |
| Step 4 | 超时取消、本地备份、同步恢复副本、释放音频内存 | Step 3 | 失败可恢复，资产可搬迁，常驻占用降低 |
| Step 5 | 摘要与搜索优化、渐进拆分 | 前四步 | 列表避开重型正文，重构范围可控 |

## 2. 共同约束

- **课节身份**：使用现有规范化 lessonKey。任务启动时尚无 noteId，也必须能确定同一课节。
- **异步目标**：请求开始时捕获 noteId、lessonKey、viewKey、baseMarkdown。响应到达后不从当前 UI 推导目标。
- **正文保护**：同一 readwrite 事务中比较当前正文与 baseMarkdown，再写入。发生差异时保留待应用结果，提示用户重新查看。
- **局部更新**：每个操作只修改明确字段。事务串行执行不能自动识别过期内容。
- **文字稿资产**：人工编辑、粘贴、导入的文字稿属于用户资产。无法判断来源的旧文字稿保守保留。
- **同步边界**：ETag 防止远端文件竞争写入，不保证笔记内容合并无损。本轮用本机恢复副本降低损失，仍保留此限制。
- **临时恢复数据**：撤回快照仅在本机保存，不进入默认 WebDAV 或本地 v1 备份。界面应说明完整备份包含当前学习资产，不含撤回历史。
- **迁移**：已有笔记、截图、练习和会话必须可读。迁移失败保留旧数据，重新运行不能重复导入。

## 3. Step 1：止血修复与检查入口

### 1A. 修复 AI 修订和撤销

入口：`src/lib/workspace/discussion.svelte.ts` 的 `DiscussionHostHooks`、`sendDiscussion`、`undoLastRevision`；`src/lib/workspace/controller.ts` 的 `configureDiscussionHost`。

已知缺陷：调用传入三个参数，回调实现只接收两个，导致会话数组被当成笔记 ID。撤销接口也存在声明与实现不一致。

执行步骤：

1. 将修订参数改为具名对象，包含目标笔记、目标视图、原文、修订结果和本次新增会话。统一类型声明、实现和所有调用。
2. 请求开始时捕获目标。切换笔记或视图不得改变保存对象。
3. 在一个数据库事务中比较 baseMarkdown、更新对应视图，并追加本次修订会话。不要用请求开始时的完整会话数组覆盖期间新增的消息。
4. 原文已改变时拒绝自动覆盖。保留模型结果和用户草稿，提供查看或复制结果的简单入口，不增加合并工作台。
5. 保存失败时保留结果供重试。重试保存不能再次调用模型。新增会话用本次请求 ID 去重，避免保存重试重复追加。
6. 撤销参数同样携带 noteId、viewKey、待恢复原文和预期当前正文。撤销不得覆盖修订之后的新编辑。
7. 更新成功提示。当前页面已切换时，明确提示原笔记保存成功。

验收：正常修订后正文和会话均落库；请求中切换笔记或视图不串写；人工编辑后迟到的 AI 结果不覆盖；保存失败可重试；重复保存不重复追加会话；撤销不影响其他笔记。

### 1B. 建立必要检查

入口：`package.json`、`tsconfig.json`。

执行步骤：

1. 添加直接依赖 TypeScript 和 svelte-check。使用 `wxt prepare` 生成所需类型，再运行 svelte-check；核对当前版本参数。
2. 添加 `typecheck`、`test` 和 `check` 脚本。`check` 执行类型检查、核心测试与构建。
3. 优先使用 Node 内置测试工具。依据项目 Node 版本选择可用的 TS 编译或执行方式，不假定所有 Node 22 小版本都支持直接执行全部 TS 语法。
4. 核心测试优先覆盖修订目标、正文比较、缓存清理和现有纯解析函数。数据库事务需要模拟 IndexedDB 时，再增加必要的测试依赖。
5. 记录首次类型检查发现的存量问题。修复真实错误，不使用 any 或全局关闭严格检查来清零。
6. 不强制引入 lint 和远程 CI。已有相关配置时接入相同检查命令。

验收：干净安装后检查命令可运行。错误的修订参数会被类型检查捕获。Step 1 完成时检查通过，未运行的浏览器场景另行列出。

## 4. Step 2：任务与缓存安全

### 2A. 使用 Web Locks 保护任务与孤儿判断

入口：`controller.ts` 的 `generate`、`retryVisualAnalysis`、`reconcileOrphanedRunningNotes`，后台任务入口及清理入口。

采用浏览器管理的 Web Locks。实施前在真实扩展页面验证所需上下文共享同一锁空间。持锁主体必须与完整任务生命周期一致。

执行步骤：

1. 抽取一个小型锁辅助函数。锁名使用 `keji-lesson-` 加规范化 lessonKey。
2. 在启动同课节生成或视觉改写前申请独占锁。使用非等待申请；未取得锁时提示任务已在另一工作区运行，避免排队后意外调用模型。
3. 在锁回调中 await 完整流程，包括最后一次保存。不能发出后台请求后立即退出回调。
4. 孤儿判断也尝试取得同一把锁。取得后重新读取最新笔记，再决定是否把残留 running 状态标记为中断。未取得锁时不修改状态。
5. `navigator.locks.query()` 和后台活跃集合只用于状态展示。不得采用“查询无锁，然后写库”的两步判断。
6. 清理单课节缓存时使用相同互斥规则。清理全部时逐课节处理，跳过活跃课节并报告跳过数量。
7. 页面关闭后不承诺任务继续执行。保留已有检查点，下一次打开后判断是否可续跑。文字稿或生成输入改变时不能使用旧检查点。
8. 核对后台请求在页面关闭后是否仍可能保存结果。若后台直接写库，该写入必须纳入持锁生命周期，或让后台只返回结果，由持锁调用方保存。
9. 未验证锁 API 可用时禁止静默退回不安全并发。给出明确错误，并记录环境限制。

验收：A 生成时 B 打开库不改变状态；两个页面同时启动同课节只有一个成功；页面隐藏不被误判中断；关闭页面后锁可释放；后台重启不让第二个任务越过仍存在的页面锁；孤儿判断与任务启动竞争时不会互相覆盖。

### 2B. 清缓存只删除可重建数据

入口：`notes-db.ts` 的 `stripNoteIntermediateFields`、`stripIntermediateFromNotes`；`lesson-cache.ts`；`transcription.svelte.ts`。

执行步骤：

1. 删除清理中的 `complete: hasMarkdown ? true : note.complete`。清理不得改写 complete、generationStatus 或删除未完成任务的 generationProgress。
2. 给文字稿记录来源和是否人工修改。字幕、ASR、导入、手动编辑的入口均需设置来源。
3. 先确保编辑/导入文字稿持久化，再清其 OPFS 副本。旧数据来源不明时保留。
4. 默认清理音视频文件和确认可重建的过程结果。笔记正文、截图、会话和学习进度保持原值。
5. 保留未完成任务恢复所需的文字稿和 modelMarkdown。完成任务的临时结果仅在确认没有资产用途后删除。
6. 清理函数在事务中读取最新笔记并修改明确字段，不能将早先读取的整条旧记录写回。

验收：生成 1/4 段后清缓存仍为未完成且可恢复；手改/导入文字稿仍存在；另一工作区正在用的课节缓存被跳过；清理前后正文、截图、会话和复习数据一致。

## 5. Step 3：局部事务与少量撤回快照

### 3A. 将全量保存改为明确操作

入口：`notes-db.ts`、`persistCurrentNote`、`persistGenerationJob`、后台消息路由与 `workspace/ui.ts`。

执行步骤：

1. 为 callBackground 建立请求/响应类型映射。先覆盖本次涉及的消息，再逐步覆盖其他消息。不引入 RPC 框架。
2. 增加或复用局部操作：修改标题/批注/标记、修改指定视图、追加会话、修改练习内容、提交单题答案、提交单卡复习结果。
3. 每个操作在一个 readwrite 事务中读取最新记录，仅改目标字段。
4. 生成检查点只更新目标视图和必要生成字段，不能覆盖用户标题、批注、会话和学习进度。
5. 正文编辑、AI 修订、重新生成使用 baseMarkdown 比较。连续生成检查点以最后成功写入的正文为下一次比较基线。
6. 比较失败时停止自动覆盖并保留待应用结果。禁止拿最新正文当新基线盲目重试旧内容。
7. 新建笔记和导入可以使用完整记录。普通编辑路径逐步停止发送完整 NoteRecord。
8. 用 BroadcastChannel 或现有扩展消息广播“笔记已变化”，只携带 ID 和变更类别。其他页面重新读取数据；有未保存草稿时不替换草稿。
9. 复用现有闪卡原子更新方式。自测答案也应按题更新，避免不同题作答互相覆盖。

验收：A 改正文、B 复习均保留；A/B 改不同元数据字段均保留；两份过期正文只允许第一份自动保存；生成检查点不覆盖新增会话或标题；更新通知不清掉编辑草稿。

### 3B. 本机保留三份覆盖前快照

执行步骤：

1. 建立一个小型本机快照 store，按 noteId 和 viewKey 管理。每个视图最多保留最近三份不同正文。
2. AI 修订、重新生成覆盖、手动保存前记录旧正文。一次生成只记录首次覆盖前内容，不为每个检查点新增快照。
3. 初版快照保留自包含 Markdown。无需图片哈希、引用计数或跨设备历史链。
4. 提供简单的查看/恢复入口。恢复仅修改对应正文，并按当前正文比较规则保存。
5. 快照创建和正文替换在同一事务内完成。快照写入失败时不继续覆盖，报告失败。
6. 删除笔记时清除所属快照。默认本地备份与 WebDAV 均不导出快照。

验收：重开页面后可恢复；每视图不超过三份；恢复不回退会话和学习进度；快照不会进入 WebDAV 文件；重复检查点不会挤掉覆盖前正文。

### 3C. 收敛练习存储路径

1. 闪卡只写专属闪卡字段，自测只写 quizState。旧模板保存在 markdown 的内容通过集中兼容函数读取。
2. 两种生成入口复用解析、保存和展示规则，不强制复用完全相同的请求编排。
3. 长文字稿直出练习继续分段。已有精简笔记提炼练习可以单次请求，超长时仍需分段。
4. 替换题目或卡片内容时，不将旧答案或复习状态错配到新内容。

验收：长视频直出练习不被改为单次超长请求；两种入口均可显示和导出；旧笔记正常打开；新题不继承无关答案。

## 6. Step 4：请求韧性、备份与资源释放

### 4A. 请求超时与 AI 助教取消

入口：`llm-service.ts` 的 `postChatCompletion`、讨论 controller、`DiscussionPanel.svelte`、后台取消处理。

1. 组合用户取消与超时信号。计时范围包含响应正文读取，并在 finally 清理计时器和监听。
2. 初始默认值：连接测试 20 秒，文本和讨论 300 秒，音频和视觉 600 秒。使用命名常量，后续按测量调整。
3. AI 助教发送期间提供取消按钮。通过本次 requestId 中止对应后台 AbortController，不影响别的请求。
4. 超时、取消、网络错误、模型错误和本机保存失败使用不同提示。发送失败保留输入。
5. 取消后不调度后续分段，不应用迟到响应。所有完成路径释放 busy/sending 状态。
6. 本轮不扩展自动付费重试策略。超时或断网后结果未知时，用户决定是否重新调用。保存失败只重试保存。
7. 排查本次修改路径中的空 catch。关键保存失败不能被吞掉，允许忽略的清理失败需要明确理由。
8. 阶段、取消和错误保持可见。分段数、并发数、重试计数放在可选详情或诊断日志，不堆到主操作区。

验收：模拟永不返回、取消、无效 JSON、429/5xx 和保存失败。界面均退出忙碌状态；取消不串请求；保存重试不产生模型调用；日志无密钥和完整课程内容。

### 4B. 本地完整备份入口

入口：`webdav-sync.ts`、`notes-db.ts` 的 `importNotes`、笔记库管理菜单。

1. 提取现有 `keji-notes-backup-v1` 序列化与验证代码，供 WebDAV 和本地入口复用。
2. 增加“导出完整备份”“导入备份”。包含当前所有视图、文字稿、内嵌截图、会话、练习内容、作答/复习结果和删除墓碑。
3. 纳入 Step 2 中尚未生成笔记的用户文字稿资产。若现有 v1 容器不能无损表示，增加可选字段并保持旧 v1 可读，明确兼容限制。
4. 排除密钥、WebDAV 凭据、原始媒体缓存及本机撤回快照。不要因为字段缺失而导出 chrome.storage.local 全部内容。
5. 读取文件前检查体积。沿用现有 200 MiB 限制，并验证格式和必需字段。损坏文件不能触发写库。
6. 默认沿用现有导入合并规则。确认说明明确：按更新时间合并，可能替换当前内容；同时应用下面的恢复副本保护。
7. 验证数据库事务失败时不留下部分笔记。对独立的文字稿资产导入，如无法跨存储原子提交，报告实际已导入范围并支持幂等重试，不能谎称全量回滚。
8. 重复导入不能产生重复课节。导入完成显示新增、更新和跳过数量。

验收：新浏览器资料目录中恢复后，当前资产一致；重复导入幂等；损坏或超限文件不改旧库；配额失败明确报告；备份不含凭据、缓存和撤回历史。

### 4C. 同步保留轻量恢复副本

保留现有更新时间合并与 ETag 条件写入。本任务提供恢复能力，不宣称解决多端并行编辑。

1. 下载或本地导入将覆盖不同内容时，在同一个笔记写入事务中保留旧本机记录。远端墓碑将删除本机记录时也先保留。
2. 每个笔记最多保留最近三份不同的导入/同步前记录，存在独立本机恢复 store。该副本包含当前正文和学习状态，不包含其他快照，避免递归膨胀。
3. 恢复副本不上传 WebDAV，不计入普通笔记列表，不创建重复课节。删除本机主记录不能同时删除本次为同步删除创建的恢复副本。
4. 提供一个简单的恢复列表，可导出该记录或明确恢复。恢复作为当前本机修改，更新修改时间并处理对应墓碑。
5. 同步覆盖普通笔记编辑使用的同一数据库事务内的最新记录。禁止在下载前取本机快照，然后用该快照覆盖下载期间发生的修改。
6. 保留 412 等远端变更保护。失败时提示重新同步，不盲目覆盖。
7. 用简短说明告知更新时间合并规则和恢复入口。无需双栏合并编辑器。

限制：恢复副本有数量上限且仅在本机存在。未被保留在本机的远端版本、不同 ID 的同课节墓碑问题，以及多端练习结果的无损合并仍未解决。按课节分文件也不能自动解决同课节冲突。若用户需要同时离线编辑多设备，另行设计同步方案。

验收：A 改正文、B 稍后复习导致旧正文获胜时，被覆盖的本机正文可恢复；同步删除后可找回；重复同步不反复制造相同副本；恢复不自动重传旧整库；快照容量失败时停止本次覆盖并报告。

### 4D. 及时释放解码后的音频

入口：`offscreen/main.ts` 的 `clearDecodedLessonAudio`、解码缓存及转写终止路径。

1. 记录哪些流程使用 decodedLessonAudio：全量转写、直接音频生成、选区重识别等。
2. 在全量使用结束、失败和取消时释放已无消费者的 AudioBuffer 及关联引用。保留 OPFS 压缩音轨。
3. 共用音频的任务不能被另一个任务的 finally 清理破坏。使用现有串行规则或一个小型消费者计数，不建立通用资源管理框架。
4. 选区连续重识别可保留短时缓存，避免每次立即重解码。依据现有行为和测量确定时长，不新增复杂设置项。
5. 测量 10、60、180 分钟输入的准备时间、峰值与结束后占用。记录采样率、声道数和测量方式。
6. 参考 PCM 量级：16 kHz Float32 每分钟每声道约 3.66 MiB。此估算不包含解码器、压缩输入、WAV 和 Base64 临时副本。

验收：任务结束后解码缓冲不继续固定驻留十分钟；其他消费者不受影响；选区重识别仍正常；取消后资源可回收。此步骤降低常驻占用，不承诺消除完整解码的峰值。

### 4E. 文档与支持范围

1. 核对 README 的端点数量、转写协议、缓存和关闭页面行为。当前源码与旧文档不一致时，以实际验证结果更新说明。
2. 本轮仅维护 Chrome/Edge。若 `build:firefox` 仍存在，移除该未维护入口，避免把构建成功当成运行兼容。
3. 不重复改造已完成的工具栏和菜单。只加入本轮确需的取消、恢复和备份入口。

## 7. Step 5：大库性能与渐进拆分

### 5A. 先增加摘要和搜索投影

入口：`notes-db.ts` 的 `getAllNotes`、`listNotes`、`saveNote`，笔记库加载和搜索。

1. 构造 50、200、500 条含截图笔记的数据集，记录列表、搜索、保存耗时及完整正文读取次数。
2. 建立轻量 summary store。包含列表所需字段和去除 Base64 的搜索文本。正文先保留现有存储。
3. 所有保存、练习更新、删除、恢复和导入路径，在同一事务中更新对应摘要。为这些入口建立清单，避免漏更。
4. 旧记录分批回填摘要。迁移未完成时允许明确的临时回退；完成后列表和搜索禁止 getAll 完整正文。
5. 搜索第一版允许扫描纯文本投影。无需全文搜索引擎。保留原有可搜索内容范围。
6. 到期闪卡数量需要随时间变化。摘要保存足够的轻量到期信息，不能永久缓存写入时的 due 数值。
7. 给 lessonKey 增加普通索引，避免保存查重全表读正文。不要直接加唯一索引导致旧重复记录升级失败。
8. 依据列表量决定是否添加数据库游标分页。不要把前端“加载更多”当作数据库读取优化。

验收：迁移完成后列表与搜索不读取完整笔记或图片；修改、导入和删除后摘要正确；旧库升级中断可继续；同一数据集给出前后测量结果。

### 5B. 图片分离仅在测量证明有需要时实施

触发条件：摘要优化后，单篇读写、内存或备份体积仍有明确瓶颈。未触发时记录结论，跳过本项，不影响前四步交付。

1. 按 noteId 归属保存图片资源，不做跨笔记全局内容去重和引用计数系统。
2. 先写资源并验证，再替换正文引用。迁移失败保留旧 Base64 内容。
3. 预览、模型输入、ZIP 与 v1 备份共用资源解析器。备份可重新内嵌图片以保持兼容。
4. 本机撤回和恢复副本继续保存自包含内容。若改变该决定，必须先明确快照资源生命周期，不能让恢复图片失效。
5. 覆盖视图时检查同笔记当前各视图的引用再清理。删除笔记只删除所属资源。恢复副本仍可独立还原图片。

验收：导出、模型画面输入和恢复均不缺图；升级中断可重试；删除一篇笔记不影响另一篇；不引入跨设备历史资源 GC。

### 5C. 只提取最重的两个职责

1. 沿用现有 `quiz.svelte.ts`、`discussion.svelte.ts` 的协作风格，先提取生成编排，再提取库列表/筛选管理。
2. 提取时写明状态所有者。用少量明确回调与参数连接，禁止新模块反向导入 controller 形成循环。
3. 保持行为不变。模块拆分不要与数据库迁移、提示词改写混在同一次变更。
4. 在触及的组件中逐步替换 DOM ID Proxy，使用显式引用或组件状态。不要求一次移除全仓命令式 DOM。
5. note-schema 仅在具体修改需要时提取独立纯函数。暂不全面拆分。

验收：生成和列表逻辑可独立理解；无新增循环依赖；取消、续跑、切换课节与筛选行为不变。完成标准是职责清楚，不是文件数量或行数达标。

## 8. 最低回归矩阵与交付记录

| 场景 | 必须检查的结果 |
| --- | --- |
| AI 修订期间切换笔记或视图 | 正文和会话保存到发起目标 |
| AI 修订期间人工编辑 | 迟到结果不自动覆盖 |
| A 生成、B 查看库或启动同课节 | 不误标中断，不重复执行 |
| 页面关闭、后台重启 | 锁和检查点行为符合已声明范围 |
| 生成 1/4 后清缓存 | 完成状态不变，恢复输入仍可用 |
| 人工文字稿清缓存 | 文字稿保留 |
| 正文、标题、复习并行写入 | 不同字段均保留 |
| 撤回或恢复后重开页面 | 正文可读，其他学习数据不意外回退 |
| 超时、取消、保存失败 | 可退出忙碌态，错误不被吞 |
| 本地备份导出后导入新资料目录 | 当前资产完整且无凭据 |
| 同步覆盖或删除 | 本机恢复副本可找到，限制有说明 |
| 长音频完成或取消 | 无消费者时释放解码缓冲 |
| 大库列表与搜索 | 不加载整库 Base64 正文 |
